# Сборка проектов Vivado

`build.tcl` собирает существующий проект `.xpr` до bitstream, используя его
исходники, constraints и настройки runs. Скрипт не привязан к имени проекта,
top module или конкретной версии Vivado; установленная версия должна быть
совместима с проектом и его IP.

```bash
vivado -mode batch -source fpga-common-lib/scripts/vivado/build.tcl \
  -tclargs project/my_project.xpr
```

Единственный аргумент: `<проект.xpr>`.
Путь к проекту отсчитывается от рабочей папки запуска, а не от папки скрипта.
В скрипте заданы четыре параллельных jobs и стандартные runs `synth_1`, `impl_1`.
Implementation run должен использовать `synth_1`.
Копия проекта не создаётся;
Vivado может сохранить изменённые настройки в исходный `.xpr`.
Результаты и отчёты остаются в штатных папках runs. Ошибка команды или этапа
возвращает код 1. Проверка timing отдельно не выполняется.
При успехе скрипт возвращает управление вызывающему Tcl-скрипту, поэтому его
можно подключить через `source` и затем создать дополнительные артефакты проекта.

Перед запуском скрипт выполняет `reset_project`: сбрасываются прежние результаты
проекта, включая runs IP и симуляции. Затем обновляется порядок компиляции,
запускается синтез и implementation. Подготовкой IP управляет Vivado.

Для создания MCS положите рядом с `.xpr` файл `flash.tcl`:

```tcl
# Объём flash в МБ, интерфейс и адрес загрузки bitstream.
set flash_size 32
set flash_interface SPIx1
set flash_address 0x00000000
```

После bitstream скрипт читает эти параметры и вызывает `write_cfgmem`.
Bitstream определяется по каталогу `impl_1` и имени top из `sources_1`.
MCS сохраняется в каталоге `impl_1` под именем проекта, например `my_project.mcs`.
Существующий MCS перезаписывается. Без `flash.tcl` сборка завершается на bitstream.

Скрипт предназначен для Project Mode с этапом `write_bitstream`. Для Non-Project
Mode, проектов с особыми подготовительными действиями и сборок с другим
конечным артефактом, например PDI для Versal, потребуется отдельный flow.
